# AgentTaskBoard

Part of the `eskais-ui` skill.

## AgentTaskBoard

`npx shadcn add @eskais/agent-task-board` installs the board and every piece it uses.

- **Snapshot or live.** `mode="snapshot"` needs `generatedAt`: it is the board's "now", shown in a banner, and times never refresh. It shows no approve or reject actions. `mode="live"` refreshes times every 30 s, paused while the page is hidden; pass `now` only for tests and screenshots.
- **One clock.** The board calls `useNow` once and passes `now` down. When you compose `TaskCard` or `TaskDetailPanel` yourself, do the same: one `useNow()` per screen, never one timer per time.
- **Labels.** English by default. Override any string with `labels={{ columns: { done: "Shipped" } }}`, or pass `labels={agentTaskBoardLabelsEs}` from `@/components/ui/agent-task-board` for Spanish, including the pieces inside (status, liveness, usage, attempts). Pass `locale` and `timeZone` for formatting.
- **Agents.** The board's root exposes `selectTask`, `setView` (`"board"`, `"table"`, `"backlog"`), `filter` (`project`, `profile`, `model`, `query`, and `stage` as a list of stage ids, where `NO_STAGE` or the "No stage" label picks tasks without a location), `openThread` and `openLink` (`openLink(taskId, labelOrHref)`, with `onOpenLink`). A Button rendered as a link has no `press` for agents, so links open through that action. In live mode with `onApproveProposal`/`onRejectProposal`, `agentApproval` decides what an agent may do: `"confirm"` (default) asks a person through your bridge's `allow`, `"allow"` acts without asking, `"deny"` hides the actions from agents. People's buttons are the same either way.
- **Detail.** `detailPresentation="dialog"` (default) opens a selected task in an `xl` dialog, two columns from 56rem; `"drawer"` slides it in from the right; `"side"` keeps a non-modal panel so the board stays usable while reading. With a modal open, the board's controls are hidden from agents, but its `selectTask`, `filter` and `setView` still work.
- **Your own task detail.** Compose `TaskDetailDialog task onClose` (or `TaskDetailPanel`) outside the board to add to its frame without copying it: `renderHeader(task)` goes under the title in the fixed header (a stats strip, a git line), `renderBeforeBody(task)` and `renderAfterBody(task)` go in the scrolling body around the task's sections (a collapsible changes section). The title, close button, `initialFocus="content"`, Escape and the agents' `setOpen` stay the dialog's.
- **Leave out what a header shows.** `TaskDetailContent` (and so `TaskDetailDialog` and `TaskDetailPanel`) takes `hide`, a list of sections (`goal`, `decision`, `acceptance`, `attachments`, `activity`, `dependencies`, `attemptsSummary`, `usage`, `links`, `location`) and detail rows (`status`, `cost`): with a stats strip and an acceptance popover in the header, `hide={["status", "cost", "attemptsSummary", "acceptance"]}`. `sections={{ main, side }}` sets each column's sections in order (`details` is the side column's list of profile, project, updated and labels); a column you leave out keeps its default. Every section is also a component that renders on its own, with the content's props: `TaskDetailGoal`, `TaskDetailDecision`, `TaskDetailAcceptance`, `TaskDetailAttachments`, `TaskDetailActivity`, `TaskDetailDetails` (`hide={["status"]}`), `TaskDetailDependencies`, `TaskDetailAttempts`, `TaskDetailUsage`, `TaskDetailLinks`, `TaskDetailLocation`; one with nothing to show renders nothing.
- **Acceptance in a header.** `AcceptancePopover criteria={task.acceptance}` is a ghost button with the label, a thin `AcceptanceBar` and `n/m`, named with the counts ("Acceptance: 1 of 3 passed, 1 failed"); it opens a popover with the `AcceptanceList` and its evidence, on hover (`openOnHover`, `delay` 300, `closeDelay` 200 by default) as well as on a press, Enter or a tap. `labels={{ title }}` and `formatSummary` word it. Render it in `TaskDetailDialog renderHeader` and pass `hide={["acceptance"]}`, so acceptance lives only in the header.
- **Columns.** The collapse toggle ends each header (shown on hover, focus, touch or while collapsed). `columnAccent="tint"` (default) marks each column with its tone, `taskStatusAccentTones` overridden by `columnTones`; the status icons follow. Order comes from `columns`.
- **Links.** `TaskView.links` (`pull-request`, `branch`, `commit`, `issue`, `external`, with an optional `state`) list in the detail's side column; a card shows an icon link to its pull request. `renderLink` replaces each, `onOpenLink` takes over the click. A thread with `href` or `onOpenThread` gets an "Open thread" button with its id in the tooltip.
- **Attachments.** `TaskView.attachments` (the `Attachment` type of `@eskais/attachments`) show as an `AttachmentStrip` in the detail's main column, images opening a `Lightbox`; a card shows a paperclip count. Agents use the strip's `openAttachment(id)`. `renderAttachments(task)` replaces the strip.
- **Location.** Pass `stages` (the `Stage[]` of `@eskais/stage-track`, in order) and set `TaskView.location = { stage, href? }`: cards show a `StagePill`, the detail's side column a `StageTrack`, and the toolbar a `StageFilter` row with counts that sets `filters.stage`. Its last toggle, "No stage" (`labels.filters.noStage`), sets `NO_STAGE` (exported from the board) for tasks without a location; it shows when some task has none, and `stageFilterNone` forces it on or off. `renderLocation(task)` replaces the track.
- **Backlog.** `view="backlog"` lists proposals and to-do tasks that aren't ready as `ListItem` rows in two `ListGroup`s with counts; live proposals keep Approve/Reject. A row opens the detail like a card. `renderBacklogActions(task)` adds your controls (a copy-command button) after Approve/Reject in each row, snapshot mode included; `renderCardActions(task)` does the same at the end of a card (pass a stable function: cards are memoized). Use the registry's `Button` and name it after the task ("Copy command for T-011"). The row's own button reads that text too, so an agent acts on the ref from its snapshot.
- **Filter controls.** `filterControls` lists the built-in controls that show (`"query"`, `"project"`, `"profile"`, `"model"`, `"stage"`; all by default). Leave one out when the host renders its own, such as a project picker: pass that value in `filters`, where it still applies, and agents can still set every key with `filter`. "Clear filters" clears only the visible controls.
- **Density.** `density="auto"` (default) applies compact spacing and controls (`data-board-density`; the radius follows the page's `data-radius`) while the board is 75rem wide or less; `"compact"` always, `"comfortable"` never. It needs `@eskais/theme-compact`.
- **Moving tasks.** `onMoveTask(move, details)` gives each board card a drag handle: cards move between columns, which changes a task's status, and within one. The board reorders nothing itself: `move` is `{ id, from, to, index, before }`, and `moveTask(tasks, move.id, move.to, move.before)` (from `@/components/ui/agent-task-board`) applies it to your tasks, keeping the order under filters. To-do's Ready and Waiting groups each take only the tasks that fit them. By default proposals stay put and nothing moves into Proposed; `canMoveTask(task, to)` changes that. Agents get `moveTask(id, status, index?)` on an agent-only "Task moves" group that follows `agentApproval` (a person confirms by default, `labels.moves.agentConfirm`), while the board's own drag moves stay hidden from them. `labels.moves` names the handle and words the announcements.
- **State.** `view`, `filters`, `columns` and `selectedTaskId` are each controlled or uncontrolled (`defaultView`, `defaultFilters`, `defaultSelectedTaskId`). Cancelled tasks are hidden until `columns` shows them.
- **Static.** It works in a single HTML file with no network (a snapshot to attach to a report): every asset is local.

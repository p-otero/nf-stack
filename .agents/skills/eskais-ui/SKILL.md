# Eskais UI

Eskais UI components are UI SDK parts styled with Tailwind v4 and semantic tokens, copied into your project as source: the files under your `ui` alias (`src/components/ui/` by default) are yours to read and edit. Load the `ui-sdk` skill as well: everything it says about parts, controllers, change details and agents applies here unchanged.

Read a component's own file before you use it: the props, variants and the comment at the top are the API. This file says which component to reach for; the references say how the bigger ones work.

Keeping screens fast (long lists, effects, React Compiler, motion) has its own skill, `eskais-perf`; building a throwaway mockup of a screen has `eskais-mockup`. Both install with Vercel's skills CLI, from the release your `components.json` names: `npx skills add p-otero/eskais-ui@<tag> --full-depth --skill eskais-perf --skill eskais-mockup -a universal -y`, or as the `@eskais/eskais-perf-skill` and `@eskais/eskais-mockup-skill` registry items.

## Install

1. In `components.json`, add the registry once:
   `"registries": { "@eskais": "https://raw.githubusercontent.com/p-otero/eskais-ui/refs/tags/<tag>/public/r/{name}.json" }`, with a release tag like `v0.2.1`. Keep the `refs/tags/` prefix: a bare `<tag>` resolves to a branch of the same name first. `main` instead gets unreleased changes.
2. Aliases: shadcn writes `registry:ui` files to `aliases.ui` and `registry:lib` files to `aliases.lib`, and rewrites the registry's `@/components/ui`, `@/lib` and `@/lib/utils` imports to `ui`, `lib` and `utils`, so any prefix works. Set `components`, `ui`, `utils` and `lib` (e.g. `"~/components"`, `"~/components/ui"`, `"~/lib/utils"`, `"~/lib"`), and make each resolve through `compilerOptions.paths` in the root `tsconfig.json`: shadcn ignores `tsconfig.app.json` and `references`, and writes into a literal `@/` folder when an alias doesn't resolve.
3. Put `@layer ui-sdk;` as the first line of the global stylesheet, above `@import "tailwindcss"`.
4. `npx shadcn@latest add @eskais/theme @eskais/font-geist @eskais/button` (any item; dependencies come along). `font-geist` bundles the default font from npm; without it the theme falls back to the system font. `font-inter` is the alternative.
5. Subpath imports work too: `"imports": { "#ui/*": "./src/components/ui/*", "#lib/*": "./src/lib/*", … }` in `package.json` with aliases `#ui`, `#lib`…, and `allowImportingTsExtensions`. Keep the extension out of the mapping: `ui` holds `.ts` and `.tsx` files, and shadcn writes the extension into each import (the Eskais README has the details). A `ui/` folder is optional: for a flat `src/components`, map `#ui/*` and `#components/*` to the same folder. shadcn then writes the imports between registry files as `#components/x.tsx` (the first alias that matches), not `#ui/x.tsx`; both resolve, so your own code can use either.
6. **Test unreleased items**: in a checkout of an Eskais UI branch, serve its built registry folder `public/r` over HTTP (`npx serve public/r -l 4173`) and point the registry at it, `"@eskais": "http://localhost:4173/{name}.json"`, so the item and every `@eskais/*` item it depends on come from the branch; switch back to the release URL afterwards. A single item can come from a relative path (`npx shadcn@latest add <eskais-ui checkout>/public/r/command.json`, with the relative path to your checkout), but its `@eskais/*` dependencies still resolve through the registry URL, so the released versions come back over the branch's. On Windows, shadcn 4.23 fails on an absolute path ("unknown scheme") and on `file:///` ("not implemented"): use a relative path or HTTP.
7. `theme` brings `utils`. Merge classes with its `cn` (`@/lib/utils`), never another one: it knows the theme's utilities, and a plain tailwind-merge drops `text-meta` from `cn("text-meta", "text-muted-foreground")`. Over a `lib/utils.ts` that `shadcn init` wrote, add with `--overwrite`.

## Choose

Each line is a need, then what to use. Props are listed by name; read the component file for their types.

- **An action, possibly async**: `Button`: return a Promise from `onClick` for pending, no double press; `loading` for work it didn't start (spinner in the leading icon's place, `aria-busy`, presses ignored, focus kept). `size="icon"` requires `aria-label`
- **An icon-only action**: `Button size="icon" aria-label` (also `Toggle` and `DialogTrigger`/`DialogClose`/`DrawerTrigger`/`PopoverTrigger`/`DropdownMenuTrigger`): shows the label, and `shortcut` keys, in a tooltip on hover and focus, never on touch; `tooltip={false}` when a visible label sits beside it, `tooltip="…"` or `{ content, side }` to describe it. `ControlTooltip label` for a control of your own. `eskais/icon-button-needs-label` flags one without them
- **A form with validation**: `Form schema defaultValues onSubmit messages label` + `FormField name label` around one control, `FormRootError`, `FormActions submitLabel`; see `references/forms.md`. `FieldSet legend` groups fields
- **A form in several steps**: `StepDialog trigger title schema defaultValues steps onSubmit labels` (or `StepForm` inline); see `references/forms.md`
- **A form in a modal**: `FormDialog trigger title schema defaultValues onSubmit submitLabel cancelLabel` with `FormField` children: closes on success, blocks Escape while pending, `confirmDiscard`, `reviewStep`
- **A labeled text input**: `Field` + `FieldLabel` + `Input`; `InputGroup` + `InputClear` for a clear button
- **A label inside the control**: `Field labelPlacement="in"` (floats up on focus or a value) or `"on"` (on the border); `Form labelPlacement` for every text field. See `references/forms.md`
- **A password**: `PasswordInput autoComplete="current-password"` (or `"new-password"`) in a `Field`: the reveal toggle is an icon button named "Show password" (`aria-label` on `PasswordInputToggle`), `aria-pressed` says whether it shows. Compose `PasswordInputControl` + `PasswordInputToggle` for a placeholder
- **A list of labels or tags**: `TokenInput tokenType="label" value onValueChange validate max tone` + `TokenInputEditor placeholder` in a `Field` or `FormField` (`string[]`, readonly arrays welcome): Enter or a comma adds, a paste splits on commas and line breaks, Backspace removes, Ctrl/Cmd+Z undoes. Remove buttons are pointer-only, named by `labels.remove`. Without `tokenType`, UI SDK's text with mention or file tokens (`renderToken`, a `TriggerMenu` child)
- **Slides with their position**: `Carousel` parts; `CarouselStatus` shows "1 of 3" (`labels.status` translates it), announced politely only on change; `useCarouselState()` returns UI SDK's `page`, `pageCount` (null until measured), `playing` for your own header. Put the header inside `Carousel`, the region
- **Rename in place**: `InlineEdit label defaultValue onValueChange validate` (a title, a list item, a tab's name): a press, Enter, F2 or typing opens a field; Enter/Tab save, Escape cancels, blur saves (`blur="cancel"` to drop); `startOn="double-click"` leaves a press to the row, `editButton={false}` drops the pencil. Agents `rename(text)` and `cancel`
- **A search box**: `SearchField label onSearch`: Enter runs `onSearch`, Escape clears only when there is text
- **Dictation, voice input**: `VoiceInput variant stream state onStart onConfirm onCancel startedAt labels` (`button` a mic toggle whose ring follows the level, `bar` with cancel, a live waveform and a timer); you get the stream (`requestMicrophone` from `@/lib/microphone`) and transcribe. `useAudioLevel(stream)` for a visual of your own; see `references/voice-input.md`
- **A modal**: `Dialog` parts; `DialogContent size` (`sm`…`full`), `DialogBody` scrolls between header and footer, a bottom sheet on narrow screens unless `sheet={false}`; `dismissible={false}` + `onDismissAttempt` for unsaved changes; `initialFocus` on the content, never React `autoFocus`; keep it mounted and drive `open` (focus still returns if it unmounts while open)
- **A small task beside its trigger**: `Popover` parts (`PopoverTrigger`, `PopoverContent` with `PopoverTitle`); `openOnHover delay closeDelay` also opens it on hover without moving focus (a press, Enter and a tap still open it; keyboard focus alone never does, use `HoverCard` for a link preview that should); `defaultOpen` works inside a dialog, even one with `initialFocus="content"`
- **Confirm in place, no dialog**: `ConfirmButton agentConfirm onConfirm` (idle content as children): the first press arms (`data-armed`, text becomes `labels.armed`), the second confirms; disarms on `timeout`, Escape or blur (`onArmedChange` reasons). `hold={ms}` confirms on a hold too. Agents `confirm` through `allow`
- **"Are you sure?"**: `ConfirmDialog onConfirm`: a returned Promise shows pending, closes on success, shows the error on failure. Children render as a callout under the description, in the dialog's tone (`calloutTone` overrides). `triggerDisabled`/`triggerPending` stop the trigger (pending shows a spinner, `aria-busy`) and refuse every open, agents' too. `labels={{ cancel }}` in the page's language ("Cancel" by default)
- **Static grouping and labels**: `Card` parts (a titled card is a `section` named by its title; `CardEyebrow`, `CardAction` as a direct child of `CardHeader`, which wraps it below the title once the title would drop under `--card-heading-basis` (11rem), `CardTitle headingLevel`, `surface`), `Badge tone`
- **Attach or upload files**: `FileUpload title description browseLabel accept maxSize maxFiles multiple` in a `Field` (the label names the browse button): a drop zone, the files as removable chips and why any were left out (`labels.rejected`, destructive tone); the value is `File[]`. Parts (`FileInputTrigger`, `FileInputDropzone target="document"`, `FileInputFiles`, `FileInputRejections`) for a button alone or a page-wide drop
- **Pick one of a list**: `Select options placeholder` (`{ value, label, disabled?, description? }`, or groups `{ label, options }`); `clearable="None"` adds a choice that sets `null`. `size="sm"` and `triggerProps` (`id`, `className`, `data-*`) style the trigger. Parts (`SelectTrigger`, `SelectContent`, `SelectItem`) still work as children
- **The platform's own picker**: `NativeSelect options placeholder clearable` in a `Field`: a styled native `<select>` for touch-heavy forms. Agents see it through its own primitive (a bare `<select>` or `FieldControl` is invisible to them)
- **Pick one of many, typed**: `Combobox` with `items` on the root, rendering options from `<ComboboxList>{(state) => state.items.map(…)}</ComboboxList>`. Static children aren't filtered, and agents then store the label instead of the value
- **Free text with suggestions**: `Autocomplete items` + `AutocompleteControl` (`AutocompleteInput`, `AutocompleteClear`, `AutocompleteTrigger`) + `AutocompleteContent` (`AutocompleteEmpty`, `AutocompleteList`) in a `Field`: the value is the text, any text is valid. From a server: `useAsyncOptions` (`items`, `status`, `filter={false}`, `setQuery` in `onValueChange`). When the value must be an option, `Combobox`
- **Pick one of a few, all shown**: `RadioGroup` of `Radio` + `RadioIndicator`, each inside a `Label`; the `FieldLabel` names the group
- **An on/off setting**: `Switch` beside its `FieldLabel` in a `Field` (lays out as a row); it renders its own thumb
- **A score out of five**: `Rating defaultValue step={0.5} deselectable size` in a `Field`; `readOnly value getValueLabel` for an average (one image). Stars fill to `--rating-fill`; `icon` swaps the star
- **A number on a range**: `Slider` parts; a range names each `SliderThumb` with `aria-label`
- **A button that stays pressed**: `Toggle`; `ToggleGroup` (`multiple`, `deselectable={false}`) for several sharing one value
- **A one-time code**: `OTPInput` with `OTPInputSlot index` per character; one native input, so paste and autofill work
- **A typed, stepped number**: `NumberInput` + `NumberInputGroup`; step buttons are named "Decrease"/"Increase", override with `aria-label`
- **A label outside a Field**: `Label htmlFor`: names any control, including a radio group, slider or switch
- **Loading, error and empty for data**: `DataState status data error onRetry labels>{(data) => …}</DataState>` from `states`: never empty while pending or after an error, keeps the last success busy during a refetch; `data` counts only with `status="success"` (`placeholderData` for a busy first paint); other props (`data-testid`, `id`) go on its root. Alone: `LoadingState label variant`, `ErrorState title message onRetry retryLabel details`, `Empty size` (`inline`, `panel`, `page`)
- **An icon**: `import { XIcon } from "lucide-react"` by name, as shadcn does; decorative by default. `Icon icon={XIcon} label` (from `icon`) when the icon alone carries meaning; see `references/styling.md`
- **A loading indicator**: `Spinner` (`size` sm, md, lg): decorative by default; `label` makes it a `role="status"`. Pulses instead of spinning under reduced motion
- **Progress or a reading**: `Progress` (`value={null}` is indeterminate) or `Meter`; the track renders its indicator. `Meter variant="ring"` with `MeterRing size` for a ring gauge; `format` on the root, or `formatValue` on the Value part for the visible text only; see `references/data-display.md`
- **A message in the page**: `Alert tone` with `AlertTitle`/`AlertDescription`, `action` for a trailing button; `live` for messages that appear later (`role="alert"` for warning/destructive, `role="status"` otherwise)
- **A status label**: `StatusPill tone` (the shared tones plus `muted`), with an optional `dot`/`pulse` (`pulse` pings three times when the status changes, then rests; `pulse="always"` keeps pinging, and each running ping makes a list or board slower to repaint); `StatusDot tone label` alone
- **Related items as chips**: `DependencyChips` with an `aria-label`; pass `onSelect` to make each chip a button agents can press
- **A number that may be guessed**: `QuantityValue` with `{ value, quality, source }`: unknown shows `—`, never 0; estimated shows `~`
- **A time**: `RelativeTime` with one `useNow()` per screen passed down as `now`, not one timer per time
- **Pass/fail criteria**: `AcceptanceList`, and `AcceptanceBar` with `countAcceptance` for a compact summary; `AcceptancePopover criteria` in a header (a label, a thin bar and `n/m` that opens the list with its evidence, on hover too)
- **Summary figures**: `StatGroup` of `Stat` parts; `StatDelta value comparison invert` for a change, read in words; see `references/data-display.md`
- **An entity's properties**: `DescriptionList layout columns labels` (`stacked`, `inline`, `grid`) of `DescriptionItem` > `DescriptionTerm` + `DescriptionDetails mono copyable`; an empty value reads `labels.empty`; see `references/data-display.md`
- **Columns of items**: `Board` with `BoardColumn` (collapsible, groups, `empty`); with `value`/`onValueChange`, `BoardColumn value` renders `BoardItem`s that move between columns by drag, keyboard and agents (`references/lists-and-navigation.md`). Cards are one tab stop with Linear-style arrows and j/k: wrap a card's primary control in `BoardCard id render`
- **Reorder a list**: `Sortable aria-label value onValueChange` of `SortableItem value` (from its `({ order }) =>` children), `handle` + `SortableHandle` when items hold buttons; or `List sortable onReorder`. Agents get `move(id, index)` and `reorder(ids)`; see `references/lists-and-navigation.md`
- **Which agent ran**: `AgentBadge agent requested?`: a provider avatar (initials on a stable color, or your `avatars`), long model ids truncate in the middle, a marker when what ran differs
- **Is an agent alive**: `LivenessIndicator` with `liveness` from your data; it never infers it from times
- **Task or attempt status**: `TaskStatusPill`, `AttemptStatusPill`, `ContextModePill`
- **Tokens and cost**: `UsageGrid` (dense tiles, for a detail view), `UsageTable` (rows, side-by-side columns) or `UsageStat`; unknown stays `—`
- **An agent task's attempts**: `AttemptTimeline`; older attempts collapse past five
- **Approve or reject a proposal**: `ProposalActions` with `agentApproval` (`"confirm"` by default, `"allow"`, `"deny"`)
- **A chat or agent thread**: `Conversation label composer` of `ConversationMessage from author avatar time streaming`, `ConversationComposer onSend`: follows the newest message, a new-below pill when scrolled up; see `references/conversation-and-activity.md`
- **Who changed what, with undo**: `createActivityLog(agent, { within })` once in the browser, `ActivityLog log label`, `log.record(…)` for your own data, `undoToast`; agents get `undo`, `redo`, `seek`; see `references/conversation-and-activity.md`
- **A whole board of agent tasks**: `AgentTaskBoard` with `tasks` and `mode`; see `references/agent-task-board.md`
- **One agent task, compact**: `TaskCard` (selects through a stretched button; chips and proposal buttons stay their own tab stops)
- **One agent task, in full**: `TaskDetailDialog` (modal, or `presentation="drawer"`) or `TaskDetailPanel` (non-modal); Escape and a close button call `onClose`; `renderHeader`, `renderBeforeBody` and `renderAfterBody` add your own parts to the dialog's frame (see `references/agent-task-board.md`)
- **A bar pinned to an edge**: `Floating side align strategy` (`sticky` default, `fixed`, `absolute`) + `FloatingContent`; put a `FilterBar` or other UI SDK controls inside. Sticky bars go last in their scroll container
- **Files and screenshots on an item**: `AttachmentStrip attachments aria-label max size onOpen`: image thumbnails open a built-in `Lightbox`, files open `href`; `+N` reveals the rest. `AttachmentThumb` alone. Agents get `openAttachment(id)`
- **Crop an image before saving**: `ImageCropper aria-label src alt aspectRatio` (a box with handles) or `mode="frame" shape="circle"` (an avatar); zoom, rotate and flip come with it, `labels` translates them. `cropImage(src, crop, { width, shape })` in `onCropCommit` makes the file
- **An image being analysed, then what was found**: `ImageScan src alt width height status progress statusText steps step regions onScan onCancel onRetry error` (`status` `uploaded` → `scanning` → `result` or `error`, driven by you): a sweep or a progress line over the image, then `regions` (`{ id, label, box: { x, y, width, height } }` in fractions of the image) as toggle buttons over it with a legend; `aspectRatio fit` for a frame of another ratio. Agents get `scan`, `cancel`, `retry`, `selectRegion`; see `references/image-scan.md`
- **A 3D model people can turn**: `ModelViewer model alt poster summary aspectRatio weights framing view clip playing material` (three.js loads lazily, only with WebGL, and draws only while something moves); **a photo becoming a 3D character** from an engine's events: `ModelScan src alt width height stage points model weights progress onCancel onRetry`. See `references/3d.md`.
- **One image of a set, full size**: `Lightbox items index onIndexChange open onOpenChange`: arrow keys, counter, fit or actual size, open original; `srcDark` follows the theme without a flash. Agents get `next`, `previous`, `goTo(index)`
- **Where work is in a pipeline**: `StageTrack stages current aria-label` (`variant="pill"` for only the current stage, `getHref` for links); `StageFilter stages counts value onValueChange` is a toggle group to filter by stage
- **Dense rows or entity cards**: `List aria-label` + `ListGroup label count` + `ListItem id title leading subtitle status meta trailing actions href/onSelect selected`; `variant="card"` for cards; `value`/`onValueChange` on `List` makes it a Listbox. Agents get `select(id)`. Buttons on a row (Open, Copy, Start/Stop) that mustn't select it, also in a selectable list or a MasterDetail: `List rowActions={(id) => [{ id, label, icon, onAction, href, disabled, confirm, tone }]}` makes the list a grid (Left/Right reach them, one tab stop) and gives agents one component per action with `run(rowId)`; `actions` on a selectable row is ignored
- **Keyboard shortcuts**: `useShortcut(keys, handler, { scope, enabled, description })` from `shortcuts` (`"u"`, `"mod+k"`, `"g i"`); `ShortcutScope name label active` for a region or an open panel; `Button shortcut="u"`, `DropdownMenuItem shortcut`; `ShortcutsDialog` once for `?`, with a `ShortcutsDialogTrigger` inside for touch. See `references/lists-and-navigation.md`
- **Tabs that switch on press**: `Tabs activateOnPress` / `SegmentedControl activateOnPress` (off by default): a mouse or pen press selects before release, like Linear and macOS; touch stays on release so scrolling doesn't select; keyboard and agents unchanged. Only for reversible view switches: actions, menu items and anything that submits always act on release
- **An inspector beside a list**: `SidePanel open onOpenChange title description actions returnFocus narrow`: non-modal, Escape closes it and returns focus to the row; `Button shortcut` inside runs while it's open; `narrow` picks `stack`, `overlay` or `sheet` on phones (`references/styling.md`). The `inbox` block composes List, SidePanel and shortcuts
- **Nested items that expand**: `Tree aria-label paths` (a file explorer: folders first, `treeFileIcon` icons) or `items` (`{ value, label, children, disabled, href }`); `checkable mode="none" checkStrategy` for tri-state checks, `toggleTreeItem` for a checked value you keep; `loadChildren` for lazy branches; `onAction` opens an item (Enter or a press); compose `TreeItem`/`TreeItemLabel`/`TreeGroup` or `TreeNodes` for custom rows. Past a few thousand rows, render `visibleTreeRows(items, expanded)` in view only. Agents expand, select and check by value
- **Thousands of rows**: `List items getItemId renderItem itemText`, flat `<ListItem id>` children, or `DataTable`: past 200 rows only the rows in view render (`virtualize="auto"`, `estimateSize`), every row stays reachable by keyboard, agents and find in page
- **A list with a detail pane**: `MasterDetail label renderList renderDetail emptyDetail header toolbar` (block): rows spread `state.itemProps(id)`, `renderDetail={(id) => ({ title, description, actions, content })}`. Stacks below 42rem of container (Back button); focus goes to the heading and back to the row. `selectedId`, `url={createUrlParam("id")}` (`@/lib/url-param`, `{ in: "hash" }`, or `{ router: hashRouter() }` from `@/lib/url-router` / your router wrapped as a `UrlRouter`; a route like `#/devices/<id>` controls `selectedId` instead), `followFocus`, `collapsible`, `resizable`, `storageKey`; `height="auto"` in a scrolling page (bounded by `--master-detail-max-height`, never a hard-coded height); `idleDetail="visible" emptyDetailTitle` keeps a live idle pane under the list when narrow, collapsible. Agents `open`/`close` it by `label`
- **A dashboard**: `DashboardGrid stats columns labels` + `DashboardCard title description actions span rowSpan status data error onRetry` (block): `{(data) => …}` children, a skeleton, error with Retry or `labels.emptyTitle` in place, rows at least `--dashboard-row-height` that grow rather than clip. `DashboardStats` of `DashboardStat label value delta loading`; `DashboardChart config` and `DashboardMeter` (a ring) fill a card
- **A settings page**: `SettingsPage url sections currentSection onSectionChange` + `SettingsSection id title description actions` of `SettingsRow label description` (a `Field`; `field={false}` for a button), `SettingsFacts` (a `DescriptionList`), `SettingsDangerZone` of `SettingsDangerAction … agentConfirm disabled pending` (block): sticky nav or a picker, current section on scroll, scroll by id (hash routers); links take their href from `url` (`createUrlParam("section", { router: hashRouter() })` → `#/settings?section=id`), `navigation="buttons"` for scroll-only buttons. Going to a section focuses its heading, by mouse, key or Back, and a section the URL names that renders later (after its data loads) is scrolled to when it mounts unless the person has acted since. `--settings-top`
- **A table over a server**: `ServerDataTable label source columns filters filterUi urlState labels`: the server filters, sorts (`sortField` on a column) and pages; page numbers, previous and next, or load more follow the source. See `references/server-data.md`
- **A list that loads as you scroll**: `ServerList aria-label source renderItem itemText labels`: ListItem rows, virtualized, the next page when the end shows and a Load more button; see `references/server-data.md`
- **A branch's history**: `CommitHistory aria-label commits branch branches onBranchChange` (newest first, `git log --topo-order`): one line per commit, merges open their branch on a side lane, Enter or a press opens a commit's details, `status: "pending"` spins until it lands; `view="branches"` with `branches={[{ name, head }]}` draws every active branch in its own lane with a pill, and the select or a pill shows one branch alone; `ServerCommitHistory source filter` pages it. Agents `expandDetails`, `expand`, `copyHash`, `selectBranch`, `focusBranch`, `listBranches`; see `references/git.md`
- **A repository's files**: `GitTree aria-label files onOpenFile current`: paths or `{ path, status }` (added, modified, deleted, renamed), folders first, virtualized; `GitFileChip path` and `GitBranchChip name` inline in text
- **Options from a server**: `ServerCombobox source getLabel value onValueChange` (`multiple` for chips) in a `Field`: searched on the server as you type, more at the end of the list
- **A diff or a code review**: `TextDiff oldText newText language` for two texts; `GitDiff patch` (or `files`) for a patch with a file tree, viewed checkboxes, j/k between hunks and `onLineSelect` for comments; see `references/diffs.md`
- **Paged data from any backend**: a `PageSource` from an adapter (`pagedSource`, `offsetSource`, `cursorSource`, `relaySource`, `linkHeaderSource`, `springPageSource`, `springSliceSource`, or `arraySource` in memory); hooks `useServerPage`, `useServerInfinite`, `useServerQuery` (not paged), `useSourceMutation` (`settle` writes the answer). See `references/server-data.md`
- **Filters for a backend**: `defineFilters` once, then `toFilterAst` and a serializer (`queryParams`, `jsonAst`, `rsql`, `odata`, `springFilter`, `graphqlWhere`, `searchOnly`); `FilterSearch`, `FilterChips`, `FilterPanel` edit it and `createUrlCodec` keeps it in the URL
- **A page's column**: `PageLayout width header` (`dense`, `wide`, `full`; `variant="workspace"` for app screens). Renders `<main id="main">` only with `as="main"`, since the shell may own `<main>`; never a live region
- **A titled block on a page**: `Section title eyebrow description action footer headingLevel surface padding`: Card composed; `surface="dashed"` for a create tile, `"none"` for no box
- **The top of a landing page**: `Hero eyebrow title titleMuted titleBreak description actions aside install align decoration headingLevel` (block): side by side or centered by container width, the install command a copyable CodeBlock
- **A page section's heading**: `SectionHeading eyebrow title description actions align headingLevel headingId` (block); give the `<section aria-labelledby>` the `headingId`
- **A grid of feature tiles**: `Bento columns` + `BentoTile span rowSpan eyebrow title description href onFollow` (block): one column, two from 48rem of container, `columns` from 64rem; children are the live demo
- **Numbered instructions**: `Steps orientation` + `Step title description` (block): an `<ol>`, side by side on wide containers; children such as a CodeBlock
- **A page footer**: `SiteFooter brand description groups bottom` (block): groups are `{ title, links }`, each a named navigation of muted `Link`s that take any Link prop
- **An application's frame**: `Shell routes groups currentHref onNavigate brand actions sidebarHeader sidebarFooter labels storageKey` (block): skip link, Topbar with ⌘K search, a grouped Sidebar (`tone: "muted"` groups; a drawer when narrow), a palette whose Go to reaches every route, a MobileNav of `mobile: true` (or `{ order }`) routes and `<main id="main">`; a route's `placements` (`sidebar`, `mobile`, `more`, `palette`) limits where it shows. `onNavigate(href, route)` for a router, else plain fast links or `#/route` hrefs; `currentHref` is an href or a matcher. The palette opens empty and one Escape closes it (`searchQuery`/`onSearchQueryChange` to control it). `sidebarShortcut="mod+b"` (opt-in) toggles the sidebar; `useShellSidebar()` inside, or your own `useSidebarState()` passed as `sidebar`, reaches its state. Pages go in `PageLayout`; an editor or workspace that fills the height takes `main="fill"` (or a route's `main: "fill"`); `--shell-height` and `as="div"` in a pane
- **A documentation page**: `DocsLayout topbar sidebar header toc as` (block): an app shell, a `Topbar` with `<SidebarTrigger {...sidebar.triggerProps} />` in `leading`, a `Sidebar {...sidebar.sidebarProps} collapse="hide" trigger={false}` that sticks under it (`--topbar-height`) at the full height, `header` (a `DocsBreadcrumb`) above the page, with `const sidebar = useSidebarState({ storageKey })`. Without a topbar, `--docs-top` in `style` clears a header of your own. `DocsToc items` with `useTocItems(ref)`, `DocsPager previous next`
- **A new landing page**: Copy `@eskais/landing-page`: Hero, SectionHeading, Bento, Steps and SiteFooter with the copy in one `content` object. Edit props and slots, don't hand-write layout
- **A public site's header**: `SiteHeader label brand items actions renderLink`: a floating pill; links that don't fit move into "More" (measured, in order), `items` with children become dropdowns, a drawer with every link on narrow screens, `data-scrolled` once the page scrolls. Put a `SkipLink` before it
- **An app screen's header**: `Topbar brand leading center centerCompact trailing`: sticky, a bottom border, `centerCompact` replaces the centre on narrow screens. `<Topbar leading={<SidebarTrigger controller={sidebar} collapsed={collapsed} />}>` is the one pattern for every width: with the `Sidebar` given the same `createSidebarController()` and `trigger={false}`, it collapses the rail on wide screens and opens the sidebar's drawer on narrow ones, where the `Sidebar` then renders no drawer button of its own (`narrowTrigger` overrides that)
- **Navigation on a phone**: `MobileNav label items overflow`: a bottom tab bar of five slots (icon over label, `current`, `badge`). Up to five `items` fill them when there is no `overflow`; with `overflow` or more than five items, four stay and the fifth slot is More, which opens the rest. Labels shrink to the meta size and wrap to two lines rather than truncate, shown at `narrow:` only unless `always`. Hide the `Sidebar` with `narrow:hidden` and give the page `narrow:mb-(--mobile-nav-offset)` so it ends above the bar
- **Skip past navigation**: `SkipLink` first in `<body>` (text required; `target` is an id or ref, default `"main"`; focuses it without changing the URL, safe in hash routers), with `PageLayout as="main"` or your own `<main id="main">`
- **Many tabs in little space**: `TabsList` scrolls on its own when its tabs don't fit (`scrollable="auto"`): edge fades, pointer-only scroll buttons (aria-hidden, not for agents), arrow keys reach every tab, works in rtl. `scrollable={false}` opts out
- **A page title**: `PageHeader title eyebrow description actions tabs breadcrumb headingLevel`; `tabs` holds a `TabsList` inside a `Tabs` that wraps the page; actions wrap below the title on narrow screens
- **A date typed, no calendar**: `DateInput defaultValue min max unavailable locale` in a `Field` (ISO value, `null` until complete; `granularity="minute"` adds the time); `DatePicker` when a calendar helps
- **A colour**: `ColorPicker defaultValue space="oklch"` in a `Field` renders an area (every pixel a colour the picker can hold: past the gamut's edge it shows the gamut-mapped colour a drag there commits), a hue slider, a swatch and a text field; compose `ColorPickerSwatches` presets, `ColorPickerChannelInput`, `ColorPickerEyeDropper`, or put the parts in a `Popover` opened from a `ColorPickerSwatch`. Save in `onValueCommit`
- **A hue picked by its light**: `PrismPicker label defaultValue onColorChange` turns a prism so one wavelength (380 to 700 nm, the value) leaves through a slit; `onColorChange` gets `{ hex, oklchHue, hslHue, wavelength }`. Spectral colours only: for magentas, alpha or a typed colour use `ColorPicker`. The stage is dark in every theme; agents call `setWavelength` or `setHue`, and a purple hue fails with why
- **A date and a time together**: `DateTimePicker value onValueChange min max locale timeZone labels={{ time }}` in a `Field`: one local `"YYYY-MM-DDTHH:mm"` value; the time has its own label, which must not repeat the date label's words; `TimeInput` alone for a time of day
- **Dates, layout or data table**: `Calendar`/`DatePicker` (ISO, `locale`, `timeZone`), `Carousel`, `Resizable`, `Sidebar` (rail, drawer; `SidebarGroup collapsible open defaultOpen onOpenChange` folds a section under its label, like a docs tree), `DataTable` (typed columns with `wrap`, `cellClassName`, `headerClassName`; `renderPagination`; `navigation="cells"` for spreadsheet-style arrows), `PageHeader`, `FilterBar` (a Toolbar)
- **Code to show or copy**: `CodeBlock code language title` (`ts`, `tsx`, `js`, `jsx`, `json`, `css`, `html`, `bash`, `md`, `diff`; parsers load on first use), `lineNumbers`, `highlightLines`, `wrap`, `maxHeight`, `onCopy`; `CodeTabs files aria-label` for several files; `Code` inline. Colours are `--syntax-*` tokens; agents read the code and call `copy`
- **Live process output (dev servers, builds, a local environment)**: `const store = createLogStore({ maxLines })` once, outside render; `store.append({ text, source, level, time })` or `store.write(chunk, { source })` from a socket or child process; `LogViewer store label sources timestamps isError actions` in a box with a height. It follows the end, filters by source, searches, colours ANSI on theme tokens, steps through errors (F8) and copies plain text; agents read the shown lines and call `filter`, `search`, `nextError`, `copy`, `jumpToEnd`. Never render a log as a `.map()` of lines or a growing CodeBlock
- **A link**: `Link variant` (`inline` in prose, `nav`/`muted` in lists, `standalone`, `plain` inside a styled row or card), `external`, `newTab`, `current`, `render` (a router link). `onFollow` takes plain clicks for client routing and gives agents a `follow` action; links without it are invisible to agents. `onNavigate` routes on the client (press, click, Enter) without that action, for a sidebar or a pager. `onIntent(href)` runs on a 65 ms hover, focus or a mouse press, to preload the route. `ButtonLink variant size` (from `button`) for a call to action. Both follow on press (`references/lists-and-navigation.md`)
- **Menus, site navigation, paging, ⌘K**: `ContextMenu`, `Menubar`, `NavigationMenu`, `Breadcrumb`, `Pagination page pageCount onPageChange labels`, `CommandDialog` + `Command` (pass `shortcut="mod+k"` to the trigger to opt in; `CommandItem href onFollow` for commands that go to a page); past 50 commands pass them as data, `<Command items>` with `<CommandList>{(state) => <CommandRows items={state.items} />}</CommandList>`, so only the rows in view mount and the palette opens on the next frame; `Accordion`, `HoverCard` for disclosure and link previews
- **A chart**: `ChartContainer config aria-labelledby` + Recharts (`accessibilityLayer`), `ChartTooltip`/`ChartLegend` + `…Content`, `ChartDataTable data labelKey keys` (typed from your rows). Every series meets 3:1 on the card, aqua (`--chart-3`) only just, so still add a legend or value labels. Series with a meaning take `var(--series-positive)`, `--series-negative`, `--series-target` or `--series-remaining`
- **Write or show Markdown**: `MarkdownEditor label value onChange` (debounced; `onConflict` when a new `value` meets unsent edits) keeps the Markdown byte for byte and shows marks only while the caret is in their span; a whole note with YAML frontmatter starts with the caret after it, and `frontmatter="readonly"` keeps people from editing the block (a new `value` still replaces it; the body stays editable when the closing fence ends the file, and text typed after it starts on a new line); `codeLanguages={markdownCodeLanguages}` from `@eskais/markdown-editor-languages` is opt-in, `labels={markdownEditorLabelsEs}` for Spanish; a `ref` gets a `MarkdownEditorHandle` (`runCommand` for formats, levels and the slash menu's blocks, `insertBlock("table" | "codeBlock" | "divider")`, `insertText(text, { userEvent: "input.type" })` to open a trigger menu, `openWikilinkSuggestions()` for an Insert link button or a slash command's `run` (it opens once the slash menu has closed; its `[[` is provisional: `getValue()` and `onChange` never include it, dismissing the list leaves the note byte for byte, a choice is one undo step, and `isComposing()` is true while the choice is pending), `insertLink`, `insertWikilink`, `wrapSelection`, `setSelection`, `scrollToLine`) for host menus and outlines. `MarkdownView markdown` renders it read-only: `onWikilinkClick` and `wikilinkHref` route wikilinks, `renderEmbed` draws `![[embeds]]`, `frontmatter="properties"` lists the YAML block (hidden by default), `extractHeadings` feeds an outline. ## Separate the layers

- **Generic UI** (open/close, pending, focus, dismissal): UI SDK, already inside the components. Don't rebuild it with `useState` + `useEffect`.
- **Reusable app behavior** (confirm before deleting, search on Enter): an Eskais UI composed component such as `ConfirmDialog` or `SearchField`.
- **Business logic** (requests, toasts, cache invalidation): always in your callback (`onConfirm`, `onSearch`). Components never run side effects of their own.

## Agents

- Create one bridge in the app with `createAgent` from `@ui-sdk/react/agent`. Pass an `allow` that checks `step.confirm` and asks a person.
- `ConfirmDialog` with `tone="destructive"` requires `agentConfirm`: a sentence saying what confirming does. It becomes `data-agent-confirm`, so agents must get approval.
- `SearchField` exposes a `submit` action to agents only when `onSearch` is set.
- Show the approval prompt as its own alert dialog (`createConfirm` from `@ui-sdk/react/alert-dialog`), not as page content: when the agent opens a modal such as `ConfirmDialog`, the rest of the page goes inert and an inline prompt can't be clicked.
- Every control needs a name a person would recognize; the agent finds it by that name.
- An Eskais action that doesn't run fails the agent's step with why (`start was refused by the app.`, `start isn't available while listening.`) instead of reporting `ok: true`; refuse agents with `if (details.source === "agent") details.cancel()`. See `references/agents.md`, which also drives the page's WebMCP tools from Playwright.
- Test every interface with the agent test from the ui-sdk skill (`.agents/skills/ui-sdk/references/agent-ready.md`).

## Style

- Use the variants (`variant`, `size`) and the semantic tokens: `background`, `foreground`, `primary`, `secondary`, `muted`, `accent`, `destructive`, `success`, `warning`, `info`, `border`, `input`, `input-strong`, `field`, `ring`, `overlay`, and `link`/`link-soft` for link text and a caret (4.5:1 on background, card and muted). `accent` is a surface (hover and selected fills) only: never a text colour or a stroke. For a stroke use `border-input-strong`, `border-primary` or `ring-ring`; for coloured text, `text-link`.
- Text fields take a soft `border-input` edge on a `bg-field` fill; checkboxes, radios and switch tracks, which nothing else identifies, take `input-strong` (3:1).
- Style state with UI SDK attributes: `data-pending`, `data-disabled`, `data-open`, `data-starting-style`, `data-ending-style`.
- Use the shape and density tokens instead of fixed sizes: `rounded-control`, `rounded-choice` (checkbox, textarea), `rounded-surface`, `h-control` (`-sm`, `-lg`), `shadow-surface`, and the spacing roles below. Surfaces that may turn glassy use `bg-<color>/(--glass-opacity)` and `backdrop-surface`.
- Theme and color scheme are app-level: `createAppearance({ colorScheme: "system" })` and `<Appearance appearance={…}>` from `@eskais/appearance` keep `.dark`, `data-color-scheme` and `data-theme` on `<html>` in sync; call `appearance.apply()` before the first render. Without any script the theme still follows `prefers-color-scheme: dark`, unless `<html>` has `data-color-scheme="light"` or `class="light"` (render one from the server for a saved light choice). The `dark:` variant does too: the theme item appends its `@custom-variant dark { … }` block below the one-line `@custom-variant dark (&:is(.dark *))` that shadcn writes, and Tailwind uses the last one, so keep it last. Don't add a theme prop to a component.
- Tones: `neutral`, `info`, `success`, `warning`, `destructive` say what a status means; `violet` is a category tone (a label or kind), never a status. For a tinted chip or surface use the soft tokens, `bg-{tone}-soft text-{tone}-soft-foreground border-{tone}-border`, not `bg-{tone}/10`; for a loading placeholder, `Skeleton` or `bg-skeleton`.
- Colour: set the seeds `--brand`, `--link-brand` (links and the caret, a blue by default), `--neutral-hue`, `--neutral-chroma` (and `--radius`) in `:root`; primary, its foreground, ring, accent and greys derive from them in light and dark. Or use a preset from `@eskais/palettes` with `data-palette="blue"` (`neutral`, `violet`, `green`, `orange`) on any element, or `createAppearance({ palette })`. To take over one colour, set that token in `:root` or `.dark`. Keep a custom brand at 4.5:1 on the background.
- Themes are attribute scopes, not separate components: `data-density="compact"`, `data-radius="none|sm|md|lg|full"` (two separate axes; `data-theme="compact"` is an alias for compact density with the md radius) or `data-theme="glass"` on any element, nested freely. A theme only sets tokens; never branch on the theme in a component.
- Pass layout classes (margin, width, grid placement) through `className`. To change how a component looks, edit its file in `components/ui/`, which you own.
- Optional: `npx shadcn add @eskais/lint-rules` adds an oxlint config with the `react` and `ui-tailwind` presets of `@p-otero/oxlint-rules` (hooks, React Compiler checks, `p-otero/spacing-tokens`) and the `@shadcn/lint` rules (`no-restyle`, `no-raw-colors`…). Extend it from `.oxlintrc.json`. It carries no type-aware rules, which need `oxlint --type-aware` and `oxlint-tsgolint`; the installed components pass `typescript/no-unsafe-type-assertion` and `typescript/restrict-template-expressions`, so turn those on in a type-aware config if you want them. The few casts the components need go through `assumeType`, `keysOf` and `recordOf` from `lib/narrow`, each with its reason.

## Keep it small

- Keep components short; split a file before it passes about 200 lines.
- Every screen state needs a decision: loading, empty, error, disabled, confirming.
- No `App*` wrapper layer and no providers the consumer must mount.
